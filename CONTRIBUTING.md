# Contributing to Kerfivo

Kerfivo is in research/design. Read [the project record](docs/README.md) before implementation. File an issue for a reproducible lab workflow problem, controller evidence or proposed feature; keep secrets and private lab files out of public issues.

Design assets are not automatically MIT because this repository is MIT. Every contributed design must include its source, creator, redistribution license, required attribution, categories, format, dimensions/units and a content hash. Only submit your own work or content whose license explicitly allows the intended redistribution. “Free to download” is insufficient. Do not relicense someone else's asset or redistribute commercial/copyright-unclear collections.

Use pull requests for contributions. Review metadata, content safety, geometry/unit fidelity and license before publication. Treat material settings as references unless independently tested on the exact lab machine; never attach an unsupported “safe preset” to downloaded artwork.

Application code requires current-source checks, real local acceptance journeys and independent review before push/release under the project instructions. Hardware integration additionally requires identified controller/driver evidence and supervised commissioning. A simulator does not establish live-machine behavior. No remote-start feature is planned for the public catalog.
